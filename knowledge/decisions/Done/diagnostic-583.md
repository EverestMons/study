## Context

The CEO wants study to be able to run "a `claude -p` setup so that i can use it locally myself without being tied to the api" — i.e. the app's model calls go through the locally installed Claude Code CLI on the CEO's own machine, consuming the Claude subscription, instead of `api.anthropic.com` with a stored API key. This diagnostic scopes that change. **It proposes no code and changes none.**

**Why the seam is favourable.** Every model call in study funnels through two functions in one file — `callClaude` (`src/lib/api.js:39`) and `callClaudeStream` (`:80`), plus `testApiKey` (`:181`) for key validation. `api.anthropic.com` appears at exactly `:45`, `:89`, `:184` and nowhere else in `src/`. Thirteen call sites across seven files consume those functions, and none of them wrap a model call in `Promise.all` — calls are sequential. So the backend is replaceable behind an unchanged call signature, and a slower backend degrades wall-clock linearly rather than exploding a spawn pool.

**Why it is not merely a swap — the three things that can kill it.**

1. **Auth mode (load-bearing).** The whole request rests on `claude -p` authenticating via the CEO's subscription OAuth rather than an API key. The CLI's `--bare` flag — the one mode that strips Claude Code's default context — documents that Anthropic auth there is *strictly* `ANTHROPIC_API_KEY` or `apiKeyHelper` and that "OAuth and keychain are never read." So `--bare` is disqualified by definition, and the non-bare path's behaviour when `ANTHROPIC_API_KEY` happens to be present in the app's environment is an unanswered question that could silently bill the API — the exact outcome the CEO asked to avoid.
2. **Per-call overhead.** Planner probe on this machine (2026-09-03, `claude` 2.1.178): a trivial `claude -p --tools "" --model sonnet --output-format json` reported `duration_ms` 2515 (wall 7.58s) and `usage.cache_creation_input_tokens` **15015**; adding `--system-prompt` and `--disable-slash-commands` gave `duration_ms` 4023 and **9092**. A fixed ~9k–15k-token input overhead survives `--tools ""`. The direct API path carries none of it. Study's bulk paths (syllabus import, skill extraction, prerequisite wiring) make many sequential calls, so this is a real budget question, not a rounding error.
3. **Transport and binary discovery.** `src-tauri/capabilities/default.json` scopes `shell:allow-execute` to two **fixed cmd strings** (`soffice` and an absolute LibreOffice path). A user-configurable `claude` path does not obviously fit that shape, and a Tauri .app launched from Finder is not guaranteed a `PATH` containing `/opt/homebrew/bin`. `src-tauri/src/lib.rs` registers exactly one `#[tauri::command]` today (`greet`, :5), so the Rust-command alternative is unbuilt.

**Working assumption, routed as a fork rather than assumed:** the CEO's "locally myself" reads as an **opt-in second backend** — the API path stays for anyone else running a released build (`release.sh`, `updater:default` in the capability set, version 0.2.26) — not a replacement. Q8 Fork 1 asks the CEO to confirm; the diagnostic must design for both and say which is cheaper.
